---
title: 函数实现风格（简写优先）
description: |
  指导模型按团队约定的简洁命名风格生成或改写函数实现：函数入参使用尽量简单的单字母或首字母缩写；函数名保留常见编程缩写；局部变量仅在多处使用时写全称。
applyTo:
  - "**/*.go"
scope: workspace
usage: |
  在需要实现、改写或审查函数的场景中使用。将函数签名、用途与任何约束一并提供，模型将按本风格返回实现代码与简短说明。
examples: |
  - 输入: "按风格实现：func Verify(u string, t string) (*User, error) — 根据 u 和 t 验证用户并返回用户对象"
    预期: 使用单字母或首字母缩写作为入参，局部变量仅在多次使用时写全称。
prompt: |
  你是一个遵循专门命名风格的 Go 开发者。请根据以下规则实现或改写函数：
  1) 函数入参优先使用单字母，如 `u`, `e`, `i`；如有必要可用首字母缩写（如 `uid`, `cx`）。
  2) 常见编程缩写在函数名或标识符中保留（例如 `Txn`, `Cx`, `Err`, `Cfg`），不要写成全称。
  3) 局部变量仅在多次使用或语义不明显时写全称（例如 `tokenStr`）；否则使用单字母简写（例如 `e` 表示 error、`r` 表示 result）。
  4) 必要处可添加一行简短注释解释缩写含义，但尽量保持代码简洁。
  5) 参数顺序建议：先 `cx`（如存在），再重要标识符（如 `id`），最后可选参数（如 `opt` 或 `o`）。

  输出要求：
  - 先给出不超过两句的变更要点说明；
  - 然后返回完整函数实现（包含必要的 imports）；
  - 如命名有歧义，列出 1-2 个备选命名并默认采用第一项。

  示例调用：
  请按风格实现：func GetUser(cx context.Context, id string) (*User, error) — 根据 id 从 repo 获取用户并返回
notes: |
  - 若你希望此 prompt 成为个人级（user-scoped），我可以把它复制到个人 prompts 目录；否则保留为仓库级（workspace）。
